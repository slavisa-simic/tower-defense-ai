# Collision/navigation audit — before implementation

Audited 2026-11-02 against the current, uncommitted Phase 6B working tree in Unity 6000.3.24f1. Existing user work is preserved. Live scene inspection receipt: `Docs/Validation/NavigationCollision/original-map-audit.txt`; reproducible inspector: `Audit.cs` in that folder.

## Exact causes

* **B/C/E:** `BattlefieldGrid.TryOccupy` reserves construction cells only and emits `OccupancyChanged`, deliberately without changing walkability or `Revision`. `DefenseDefinition` has no solid/walkable flag. `BuildManager` never installs a navigation blocker. A* reads `GetCell(...).Walkable`, so every player defense is traversable. Wire's separate cost/slow overlay is the only defense navigation integration.
* **A/C:** Danube Border has **zero** authored blocked cells. Command Post, permanent bunker walls, quarantine fence and checkpoint barriers are sprites with no Collider2D or navigation footprint. Gate art overlaps the breach corridor and needs an explicit passable opening, not a blanket sprite-bounds rectangle.
* **A/C, selectively:** Industrial Port has **163** correctly authored static blocked cells: six container-group rectangles, warehouse/maintenance/shed footprints, northern crane landmark and three checkpoint compounds. All 24 container renderers overlap blocked masks. Thus the assertion that every port container is absent from navigation is **not** supported by this saved scene. However all **three Dockside crane** renderers overlap **zero** blocked cells. Forklift parking extends beyond its shed mask. All these props have zero Collider2Ds. Sprite silhouette overhang, and walking through adjacent unblocked cranes/defenses, can look like a wholesale container-navigation failure.
* **D/F:** `EnemyMovement` edits the Transform directly along cached cell-center segments. Grid `Changed` invalidates paths, but occupancy does not generate that event. Movement never validates its next section against current walkability. Every invalidated enemy recalculates synchronously on its next tick, creating a burst. Even future blocker revisions alone would not provide local contact safety.
* **Missing blocked-route gameplay:** `EnemyCombat` damages only BaseHealth. No normal creature selects or attacks a player obstruction. `SpitterAttack` separately finds nearby defenses and launches real damage projectiles. `BorderBreachService` and `EnemySpawner` currently reject a landing if no entirely open path exists, so allowing walls without updating deployment would stall arrivals.
* **Lifecycle:** `DefenseBase.OnDied` clears build occupancy and defers destruction; there is no navigation blocker to clear and no immediate deactivation. Existing Health/Changed events already drive selection HP and Repair costs. Dismantle is the sole refund path. Wire cleanup is independently owned and must remain compatible.
* **Burrower/bosses:** Burrower already follows the same cell path and temporarily ignores Wire slow; it does not have a permanent ghosting ability. Bosses use ordinary EnemyMovement and therefore inherit the defense walkability bug. No special collision bypass is needed or retained.
* **Physics:** No named EnvironmentObstacle/PlayerDefense/Enemy physics layers exist. Current movement, selection, targeting and projectiles use grid/direct queries, not Rigidbody2D collision response. Adding colliders alone cannot repair navigation. No obstacle LOS currently exists for Spitter.

## Implementation plan and design decision

1. Keep build occupancy separate; add owner-scoped dynamic navigation blockers. Solid DefenseDefinition footprints install/remove blockers transactionally through existing construction/lifecycle owners. Wire/Mine stay walkable. Reject placement overlapping living creatures rather than trapping them inside a newly solid cell.
2. Author permanent rectangular footprints in BattlefieldDefinition and matching simple collider representations in both saved scenes using Unity APIs. Retain existing port masks and explicit gate openings; keep debris/decals/tiny cargo decorative. Validate static routes independently of player occupancy.
3. Preserve normal A* and bounded shared path cache. Add staggered, budgeted repathing and section-by-section contact safety. Add a shared, revision-cached reverse obstruction field per destination; it may consider player walls but never permanent terrain. Its first blocking cell identifies a relevant player defense and a walkable approach.
4. Add a focused structure combat state component and data-driven creature attack profiles, reusing DefenseBase/Health and existing attack/hit presentation. Stop at footprint contact range, spread attackers over reachable contact cells, invalidate targets on removal, and return to the border route as soon as it opens.
5. Update deployment and multiple-breach selection for destructible walls. Harden immediate destruction cleanup, preserve repair/upgrades/dismantle/wire/save behavior, add development footprint validation/debugging, regression tests, both-map live checks and 100/200-enemy stress cases.

The old placement code does **not** enforce a keep-one-route-open rule; it only checks terrain/build occupancy/money. Earlier project rules anticipated future route validation. This request explicitly supersedes mandatory open-route preservation: validate static connectivity and placement occupancy, then allow player walls with a real attack-through route. Permanent obstacles remain indestructible. No new art or production phase is authorized or started.
